# 直播加载与交互调整（build 45）

## 本次改动
- 分类不常驻：单个「分类」按钮打开选择面板。
- 直播预览与进房共用同一个 VLC / drawable，只切原生界面，不打开第二套网页播放器；退出回到同一直播预览。
- 进房顶部显示主播与退出，底部是原生发言框、聊天与更多；清屏可从更多或横滑触发，点击恢复。
- 翻页只接受真实竖滑造成的相邻页变化，列表追加、布局回写不得自动切台。
- 推荐页仅预取一页直播元数据；不提前拉流、不进房，过期后重新获取。
- 评论网页延迟到进房且视频输出就绪后加载，避免预览阶段抢资源。
- 显式 AVC 视频 FLV 优先（800ms 缓冲）；不能确认兼容的流直接走 HLS（1500ms），不盲试 HEVC-FLV。仅使用 SDK 明确标记、未加密、非纯音频且 URL 完全一致的 AVC 线路。
- 后台/失焦停直播，回来重连直播边缘；打开官网互动时先停原生流。

## 2026-11-28 直播起播慢：列表给的是 H.265

- 现象：直播页大多数直播间走 HLS，起播 2–7 秒，有的直到离开都没出画；少数走 FLV 的 0.4–1.0 秒。
- 原因：推荐 / 专区列表（`webcast/feed/`、`partition/detail/room/v2/`）下发的线路几乎全是 H.265（FLV 是 `_hd5.flv` 一类，HLS 也标 `VCodec=h265`）。VLC 3 的 FLV 不认 H.265，`compatibleLiveFLV` 正确地把它们过滤掉了，只剩 H.265 的 HLS。抽样：推荐页 20 间里只有 2 间有能用的 FLV。换浏览器身份、加 `support_h265=0` 都不改变。
- 同一间的进房接口 `webcast/room/web/enter/` 给的是 H.264（FLV 与 HLS 都是），抽 8 间全部如此，单次 0.3–0.6 秒。
- 修法（`DYLiveEnterClient` + `DYLiveH264Upgrade`）：列表里没有 H.264 FLV 的直播间，播放前先用进房接口换成 H.264 FLV（最多等 1.5 秒，超时照原 HLS 播，结果回来且还没出画再换）；当前与相邻几间提前换好。成功的结果留 5 分钟，失败 1 分钟内不再试。
- 进房接口匿名直连：只带对直播首页 HEAD 拿到的 `ttwid`，不带登录 cookie、不经过隐藏网页。经隐藏网页（登录 + 页面签名）发出去回的是 200 空包。
- 模拟器验证：首间 FLV 出画 0.47 秒；连续上滑 4 间都是 FLV，出画 0.37–1.8 秒，下一间在滑到之前已换好。真机未测。
- 回归：`scripts/test_follow_live_logic.py` 覆盖换线路的决策、缓存时效、超时放弃，以及进房回包解析（H.265 / 纯音频 / 加密 / URL 不一致 / 下播 / 空包）。

## 2026-11-28 切台预加载（往上滑零等待）

- 以前直播页只有一个播放器，每划一次都要停掉再重连，换成 H.264 FLV 后也要 0.4–1.8 秒。官方是下一间早就连好、解码好，划过去只是换画面。
- 现在（`DYLiveModel`「预加载下一间」）：当前这间出画后，用第二个播放器把下一间静音（音量 0）播在窗口最底层；划过去时连同画面视图一起接过来，旧的那一路立刻无声、0.6 秒后停（复用 `DYFeedLiveWarm.stopLater`，防主线程析构卡死）。
- `model.vlc` 不再是常量：界面用 `DYLiveVideoHost` 挂「当前这一路自己的视图」；回调只认当前这一路，换台后旧的那一路的就绪 / 出错不会算到新房间头上。
- 只预加载往上滑的下一间；往回滑仍是现连。省流量用流量、VLC 停播积压、线程吃紧、后台、浏览分类时都不预加载；停在一间超过 60 秒就放掉。DEBUG 可用 `DOUDUO_LIVE_NOWARM=1` 关掉对比。
- 模拟器：连续上滑 4 间都是接过预加载的那一路，接手时已经在出画（`DDLIVEPLAY … warm=1 frame=true`，就绪 0.000 秒）；往回滑现连 1.48 秒。真机未测（重点看发热、流量、两路同时解码时的耗电）。

### 省电模式自动切换（同日）

- `DYLivePreloadPolicy`：低电量模式、用流量、手机发热（thermal serious 及以上）时用 **preview**，其余用 **full**。低电量模式 / 发热状态一变化立刻按新方式重排下一间。省流量开着且在用流量时仍然完全不预加载。
- **full**：同上（两路同时播、划过去零等待），但最长只挂 20 秒（原 60 秒）。
- **preview**：下一间只播到第一帧，截一张图（720 宽，`saveVideoSnapshot` 经 `DDTryObjC` 接异常）就停，每间约 0.5–0.7 秒；截到的画面在划的过程中和现连出画前垫在那一页上（替代封面，不再写「连接直播…」），出画后被真画面盖过。画面 20 秒后算旧、停在原地会重截；90 秒以上不再拿来垫。
- 模拟器：preview 截图 0.46 / 0.65 秒后停播；划过去先显示截到的画面，现连 0.41 秒出画。full 划过去仍是 `warm=1 frame=true`、0.000 秒。DEBUG 可用 `DOUDUO_LIVE_PRELOAD=preview|full` 强制。
- 真机未测：两种模式的实际耗电、发热差别要真机看。
