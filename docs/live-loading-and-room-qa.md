# 直播加载与交互调整（build 45）

## 本次改动
- 分类不常驻：单个「分类」按钮打开选择面板。
- 直播预览与进房共用同一个 VLC / drawable，只切原生界面，不打开第二套网页播放器；退出回到同一直播预览。
- 进房顶部显示主播与退出，底部是原生发言框、聊天与更多；清屏可从更多或横滑触发，点击恢复。
- 翻页只接受真实竖滑造成的相邻页变化，列表追加、布局回写不得自动切台。
- 推荐页仅预取一页直播元数据；不提前拉流、不进房，过期后重新获取。
- 评论网页延迟到进房且视频输出就绪后加载，避免预览阶段抢资源。
- 显式 AVC 视频 FLV 优先（800ms 缓冲）；不能确认兼容的流直接走 HLS（1500ms），不盲试 HEVC-FLV。仅使用 SDK 明确标记、未加密、非纯音频且 URL 完全一致的 AVC 线路。
- 后台/失焦停直播，回来重连直播边缘；打开官网互动时先停原生流。

## 验证
- `scripts/test_live_sources.py`：6 项通过，覆盖 AVC、HEVC、纯音频误标、加密、URL 参数差异、缺少 SDK 元数据。
- `testNativeLiveRoomFlow`：分类展开/收起、原生进退房、清屏恢复、回同一房间、上滑切台及停止后的稳定性通过。
- `testConditionalTitleExpansion` 回归通过。
- 真正切到系统设置再返回：播放登记表停播/恢复链路有效，返回重连产生新的真实视频输出就绪日志。
- Release archive 与 Ad Hoc export 均成功；手机安装后读回为 1.3.3 / build 45。

## 性能口径
- 同批 4 房间在本机 ffmpeg 协议探针中解出首帧：FLV 0.097–0.316s，HLS 0.496–2.643s。这不是手机成绩，也不能证明当前 VLCKit 支持所有 FLV 编码。
- 模拟器实际 App 最近一轮 HLS 拉流到视频输出就绪：1.124s、2.012s、1.823s；一条兼容游戏 FLV 为 0.633s。不同直播间/网络时刻，不作严格前后 A/B 倍率比较。
- 模拟器 VLC 不出画的环境限制仍存在；以上以当前媒体的视频输出状态与进度为依据，不冒充真机画面首帧测量。

## 正式抖音对照与边界
- 用 `devicectl ... info apps --include-all-apps` 区分正式抖音 `com.ss.iphone.ugc.Aweme` 40.9.0 与重签测试版；默认应用列表会漏掉 App Store 应用。
- 正式版真机预览截图确认：直播有预览/进房两层；预览中有「点击进入直播间」，「直播发现」是收起的按钮，不是常驻分类条。
- 测试版样本不作为正式版证据。进房采样期间手机切到其他 App，该次进房截图无效，未把它当作正式版房间验证。
- 本轮属于网页接口/编码分析与正式版交互观察，不宣称完成原生直播 SDK 二进制逆向；礼物等官方互动仍明确通过官网入口。
- 原版 UI 采样用例默认跳过，只在显式启用时运行；采样前检查正式版仍在前台，用户使用其他 App 时停止，不反复抢回前台。
